# طرح ربات اینستاگرام استوک لند

ربات مستقل برای پیج `stock_land.ir` که جایگزین نوین‌هاب می‌شود: پاسخ خودکار به کامنت و دایرکت، پنل مدیریت PWA، و پاسخ هوشمند به سؤال‌های آزاد.

- سرور: آلمان، مسیر `/opt/instagram-bot`، سرویس `instagram-bot`، دامنه‌ی `ig.stland.ir`
- زبان: Python 3.12 + FastAPI
- پایگاه داده: SQLite (WAL) با بکاپ شبانه
- پنل: PWA (نصب روی گوشی، اعلان پوش)
- هوش مصنوعی: Claude، فقط برای پیام‌هایی که به هیچ قانونی نمی‌خورند

## ۱. معماری

```
اینستاگرام ──Webhook──▶ ig.stland.ir (FastAPI, nginx, HTTPS)
                              │
            ┌─────────────────┼─────────────────┐
     موتور قانون‌ها        SQLite            پاسخ هوشمند
     (کلمه → پاسخ)      (پیام، کامنت،       (Claude + پایگاه دانش)
                         قانون، لاگ)
                              │
            ┌─────────────────┼─────────────────┐
     ارسال به اینستاگرام    پنل PWA         اعلان پوش به گوشی
     (کامنت، دایرکت)      (صندوق، قانون‌ها)  (ارجاع به انسان)
```

جریان هر رویداد:

1. وبهوک می‌رسد → امضای `X-Hub-Signature-256` بررسی می‌شود → رویداد در صف داخلی ذخیره می‌شود → پاسخ `200` فوری.
2. پردازشگر صف: رویداد تکراری حذف می‌شود، در پایگاه داده ثبت می‌شود، قانون‌ها به ترتیب اولویت بررسی می‌شوند.
3. اولین قانون منطبق اجرا می‌شود: پاسخ عمومی، دایرکت خصوصی، یا هر دو.
4. اگر هیچ قانونی منطبق نبود و پاسخ هوشمند فعال بود: Claude با پایگاه دانش جواب می‌دهد. اگر مطمئن نبود، یا قصد خرید یا شکایت تشخیص داد، به صندوق «نیاز به انسان» می‌رود و اعلان پوش می‌فرستد.
5. هر ارسال با نتیجه، زمان و شناسه‌ی اینستاگرام لاگ می‌شود.

## ۲. مدل داده (برگرفته از ساختار دستورهای نوین‌هاب)

### Rule (دستور)
| فیلد | توضیح |
|---|---|
| `name` | نام نمایشی |
| `enabled` | فعال / غیرفعال |
| `priority` | عدد؛ کوچک‌تر زودتر بررسی می‌شود |
| `channels` | `comment`، `dm`، یا هر دو |
| `post_scope` | `all` یا فهرست شناسه‌ی پست‌ها |
| `triggers` | فهرست شرط با رابطه‌ی «یا» |
| `actions` | پاسخ‌ها (پایین) |
| `advanced` | تنظیمات پیشرفته (پایین) |

### Trigger (عبارت شروع)
| `match` | معنی |
|---|---|
| `any` | هر مقداری (معادل «هر مقداری» نوین‌هاب) |
| `exact` | برابر دقیق |
| `contains` | شامل باشد |
| `starts_with` | با این شروع شود |
| `regex` | عبارت منظم (فقط برای کاربر پیشرفته) |

مقایسه بدون حساسیت به حروف بزرگ و کوچک، با یکسان‌سازی «ی/ي»، «ک/ك»، اعداد فارسی و عربی، و حذف فاصله‌های اضافی.

### Actions (پیام‌های پاسخ)
| فیلد | توضیح |
|---|---|
| `public_replies` | فهرست متن برای پاسخ عمومی زیر کامنت؛ چرخشی تا تکراری نباشد |
| `private_replies` | فهرست متن برای دایرکت خصوصی به کامنت‌گذار (تا ۷ روز بعد از کامنت مجاز است) |
| `dm_replies` | فهرست متن برای پاسخ به دایرکت |
| `attachments` | لینک یا فایل همراه پیام |
| `buttons` | دکمه‌های پاسخ سریع (مرحله‌ی ۴) |

### Advanced (تنظیمات پیشرفته)
| فیلد | توضیح |
|---|---|
| `require_follow` | فقط اگر کاربر فالوور باشد؛ وگرنه پیام «اول فالو کن» |
| `once_per_user` | هر کاربر فقط یک بار پاسخ بگیرد |
| `cooldown_seconds` | فاصله‌ی حداقل بین دو پاسخ به یک کاربر |
| `delay_seconds` | تأخیر تصادفی قبل از ارسال (طبیعی‌تر، ضداسپم) |
| `active_hours` | بازه‌ی ساعتی فعال بودن |
| `follow_prompt` | متن پیام راهنما وقتی کاربر فالوور نیست |
| `followup` | پیگیری خودکار: `{"after_seconds": 3600, "text": "..."}`؛ بعد از زمان مشخص به دایرکت کاربر می‌رود. فقط اگر پنجره‌ی ۲۴ ساعت باز باشد می‌رسد، وگرنه در لاگ خطا ثبت می‌شود |

«محدود به یک پست» نوین‌هاب با `post_scope` پوشش داده می‌شود؛ در پنل، پست از فهرست پست‌های پیج انتخاب می‌شود. «کامنت بعد از دایرکت» یعنی هم `private_replies` و هم `public_replies` پر باشد.

### سایر جدول‌ها
- `Comment`، `Message`، `Conversation`: صندوق کامنت و پیام با وضعیت خوانده‌شده / پاسخ‌داده‌شده
- `Reply`: هر پاسخ ارسالی با شناسه‌ی اینستاگرام، قانون مربوط، و نتیجه
- `Knowledge`: پایگاه دانش برای پاسخ هوشمند (قیمت‌ها، سؤال‌های رایج، آدرس، ساعت کاری)
- `Handoff`: مواردی که نیاز به انسان دارند
- `Token`: توکن اینستاگرام و تاریخ انقضا

## ۳. پیش‌نیازهای متا

نوع اپ: **Instagram API with Instagram Login** (بدون نیاز به صفحه‌ی فیسبوک).

دسترسی‌ها:
- `instagram_business_basic`
- `instagram_business_manage_messages`
- `instagram_business_manage_comments`
- `instagram_business_content_publish` (برای زمان‌بندی انتشار، مرحله‌ی ۴)

برای پیج خودمان نیازی به بازبینی متا (App Review) نیست: اپ در حالت Development برای حساب‌هایی که روی اپ نقش دارند (Instagram Tester) کامل کار می‌کند و وبهوک هم برایشان ارسال می‌شود. بازبینی فقط برای وصل کردن پیج دیگران لازم است.

توکن بلندمدت ۶۰ روزه است و ربات هر ۳۰ روز خودکار تمدیدش می‌کند.

محدودیت‌های اینستاگرام که ربات رعایت می‌کند:
- پاسخ دایرکت فقط تا ۲۴ ساعت بعد از آخرین پیام کاربر
- دایرکت خصوصی به کامنت‌گذار فقط تا ۷ روز بعد از کامنت
- شروع دایرکت جدید ممکن نیست
- سقف نرخ ارسال؛ ربات با صف و تأخیر تصادفی رعایت می‌کند

## ۴. مرحله‌ها

### مرحله‌ی ۰: پیش‌نیاز (کار صاحب پیج با راهنمایی)
- ساخت اپ در Meta for Developers
- افزودن پیج به‌عنوان Instagram Tester و پذیرش دعوت از داخل اینستاگرام
- گرفتن توکن بلندمدت
- تنظیم nginx و HTTPS روی `ig.stland.ir`
- گرفتن خروجی همه‌ی دستورهای نوین‌هاب برای وارد کردن

### مرحله‌ی ۱: هسته
- وبهوک کامنت و دایرکت با بررسی امضا
- صف داخلی و پردازشگر
- موتور قانون‌ها با مدل بالا
- ارسال پاسخ عمومی، دایرکت خصوصی، پاسخ دایرکت
- وارد کردن قانون‌ها از خروجی نوین‌هاب
- تمدید خودکار توکن
- لاگ و بکاپ شبانه
- تست: موتور قانون‌ها، یکسان‌سازی متن، بررسی امضا، حذف تکراری
- جابه‌جایی پست‌به‌پست از نوین‌هاب: هر پست که به ربات منتقل شد، قانون معادلش در نوین‌هاب خاموش می‌شود تا دو جواب نرود

### مرحله‌ی ۲: پنل PWA
- ورود با رمز و نشست امن
- صندوق کامنت‌ها و پیام‌ها با فیلتر: همه، خوانده‌نشده، پاسخ‌داده‌نشده، پاسخ‌داده‌شده
- پاسخ دستی از داخل پنل
- ساخت و ویرایش دستورها با همان فرم نوین‌هاب: محل دریافت، عبارت شروع با شرط‌های «یا»، پیام‌های پاسخ، تنظیمات پیشرفته، پیش‌نمایش
- انتخاب از پیام‌های قبلی
- نصب روی گوشی و اعلان پوش

### مرحله‌ی ۳: پاسخ هوشمند
- پایگاه دانش قابل ویرایش در پنل
- پاسخ با Claude به پیام‌هایی که به قانون نمی‌خورند
- تشخیص قصد خرید، شکایت، یا عدم اطمینان → ارجاع به انسان با اعلان پوش
- گزارش مصرف و هزینه

### مرحله‌ی ۴: تکمیل
- فرم‌ساز (جمع‌آوری شماره، نام، مدل گوشی)
- منوی دکمه‌ای
- زمان‌بندی انتشار پست
- گزارش هفتگی خودکار (آمار پیج، پست‌های برتر، درخواست‌های پرتکرار)

## ۵. امنیت و نگه‌داری
- همه‌ی رازها در `.env` با مجوز `600`؛ هیچ رازی در ریپو نیست
- بررسی امضای هر وبهوک؛ درخواست بدون امضای درست رد می‌شود
- ورود پنل با رمز قوی، محدودیت تلاش، و نشست با انقضا
- بکاپ شبانه‌ی SQLite به مسیر جدا و نگه‌داری ۱۴ روز
- وارسی قبل از انتشار: تست‌ها سبز، مهاجرت پایگاه داده اجرا شده
- وارسی بعد از انتشار: وبهوک تست از متا دریافت شود، سرویس سالم باشد
- ثبت هر تغییر در `CHANGELOG.md` و وضعیت جاری در `STATUS.md`
